# BRLA-G2 多时间尺度观察与因果对齐协议

**状态：FROZEN / RESEARCH ONLY**

协议版本为 `emergenzix-brla-g2-multitimeframe-observation-v1`。15分钟完整K线是唯一基础源；1小时、4小时和1日K线由同一来源按UTC固定边界聚合，不能混用交易所提供的不同时间尺度结果。

## 冻结窗口

| 尺度 | K线数量 | 覆盖用途 |
| --- | ---: | --- |
| 15分钟 | 192 | 最近48小时的执行噪声与短期冲击 |
| 1小时 | 168 | 最近7天的局部反弹和交易时机 |
| 4小时 | 180 | 最近30天的主要交易结构 |
| 1日 | 180 | 最近180天的旧趋势背景 |

窗口长度属于协议的一部分。修改长度必须建立新版本和新训练/验证分区。

## 因果边界

决策时间必须落在15分钟边界。只有 `开盘时间 + 周期 <= 决策时间` 的K线可以进入观察。正在形成的1小时、4小时或日线整体丢弃，不能用部分15分钟数据估计其最终OHLCV。

所有源K线必须满足：时区明确、UTC 15分钟对齐、已经完成、非填补、连续无缺口、无重复、价格和成交量为正且OHLC有效。任一条件失败即fail closed，不允许前向填充、插值或退化到较短窗口。

## 防止未来泄漏

观察对象只包含四个完成窗口及其SHA-256，不包含未来收益、秩序标签、未来状态或交易结果。未来K线可以存在于源文件，但会在聚合前按决策时间排除；修改这些未来K线不得改变观察指纹。

四个窗口的指纹可以进入BRLA-G2阶段一输入。阶段一未来标签由另一条隔离流程生成，不能回写本观察。观察模块没有仓位、订单或自动晋级权限。

## 当前限制

本协议只冻结OHLCV时间对齐，尚未定义资金费率、OI、清算、盘口和新闻的发布时间对齐。这些异步数据必须在后续协议中按“当时实际可见时间”单独处理，不能仅按事件发生时间回填。
